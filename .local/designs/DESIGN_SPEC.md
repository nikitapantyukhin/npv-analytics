# NPV Analytics — эталонный дизайн интерфейса (спринт 03)

**Статус:** утверждённый визуальный референс для реализации через Codex.

**Назначение:** все скриншоты в `screens/` показывают согласованную композицию интерфейса. Исходный статический HTML/CSS находится в `source/`; он служит самым точным источником размеров, цветов и расположения блоков. Скриншоты имеют ширину **1600 px**, высота изменяется при прокрутке страницы.

## Иерархия визуальных источников

1. `screens/*.png` — **канонические макеты**: повторить расположение элементов, навигацию, структуру карточек, цвета, типографику, графики и таблицы максимально точно.
2. `source/index.html`, `source/styles.css`, `source/pages.js` — исходная статическая реализация макетов, предназначенная для прямого воспроизведения деталей. Можно пользоваться CSS-токенами и переносить стили, но динамические страницы должны быть разработаны на React.
3. `reference/` — исторические примеры GuardPro и Command Center, а также ранняя генеративная концепция. Они **НЕ являются каноническими** и не должны переопределять изображения из `screens/`.

## Согласованные функциональные требования

**Шесть пунктов меню:** «Обзор», «Генератор сделок», «Портфель», «Факторный анализ», «Кривые ставок», «Данные и интеграции». Пункты не переименовывать и не добавлять без необходимости.

1. **Обзор:** выбор портфеля, KPI, графики, структура кредита/депозита, последний реальный факторный анализ, статусы функций.
2. **Генератор:** простой и расширенный режимы; кредитный, депозитный, смешанный портфели; распределения сумм, сроков, ANN/RGM/SIMPLE, FIXED/FLOAT; расширенные параметры досрочек/субсидий, seed; предварительная проверка, сохранение, экспорт CSV.
3. **Портфель:** таблица, серверные фильтры и пагинация, карточка сделки **на отдельной странице**, графики платежей, NPV, исходные поля, диагностика, история.
4. **Факторный анализ:** два режима — сценарный и исторический; изменение факторов, ΔNPV, waterfall с последовательной подстановкой, детальные таблицы, расчёт отдельных сделок и целого портфеля.
5. **Кривые ставок:** четыре вкладки — «Кривые», «Сценарии», «Дисконтирование и NPV», «История кривых»; стандартные и свои сценарии, графики, таблицы DF/PV, источник и дата кривой.
6. **Данные и интеграции:** четыре вкладки — «Подключения», «Источники данных», «Запуски расчётов», «Проверки и журнал»; загрузка файлов, статусы, фоновый расчёт, диагностика, сквозной тест.

## Правила достоверности финансовых данных

**ВНИМАНИЕ. Цифры на изображениях — только иллюстративные, а не результаты реальных расчётов.** Наличие макета не означает, что соответствующий модуль уже работает. Для реальной системы:

- Использовать настоящие данные из бэкенда; не вставлять статистику или NPV из статических макетов как рабочие значения.
- Показывать «Работает» только после успешного тестирования функции. Возможные состояния: «Работает», «Ожидает интеграции», «Запланировано», а для подключения — «Не проверено» / «Доступно» / «Недоступно».
- Для неподдерживаемой функции предусмотреть полноценную вёрстку и понятное сообщение о требуемом источнике/контракте; не выполнять фальшивый расчёт по нажатию.
- Не подменять кривую дисконтирования прогнозом ключевой ставки.
- Не смешивать знаки кредитных и депозитных потоков, не выдавать частичный расчёт за полный.
- Соблюдать предварительно согласованную методику NPV, обязательно вести версии исходных сделок, кривых, CF и результатов.

## Технологии будущей реализации

React + TypeScript + Vite + Tailwind/shadcn/ui; Backend FastAPI, PostgreSQL, Redis/RQ, Docker Compose. UI можно реализовать на любом технически эквивалентном стеке, но **внешний вид desktop должен повторять макеты**. Для графиков предпочтительно Apache ECharts, для таблиц — TanStack Table.

## Проверка готовности дизайна

- Каждой PNG соответствует маршрут/экран в приложении.
- Настоящий screenshot с шириной 1600px визуально совпадает с соответствующим PNG по структуре, сетке, отступам, цветам и текстовой иерархии.
- У всех страниц одинаковые sidebar, topbar, карточки, typography и состояния.
- При изменении вкладок не появляется другой дизайн-системы.
- В макете отсутствующих данных показываются корректные empty state, а не фиктивные вычисления.

**Скриншоты и статический HTML/CSS — эталон дизайна, а не готовая реализация бизнес-логики.**
